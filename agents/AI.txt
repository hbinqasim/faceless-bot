CURRENT AGENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Research Agent

Finds latest topics.

Outputs:

latest_topic.json

Fact Checker

Verifies claims.

Outputs:

verified_topic.json

Knowledge Agent

Consumes verified_topic.json

Produces structured knowledge.

Outputs:

knowledge.json

Script Agent

Consumes knowledge.json

Produces YouTube Shorts narration.

Outputs:

latest_script.txt

Storyboard Agent

Consumes script.

Produces ONLY structural information.

Example:

Scene
Purpose
Emotion
Shot type
Visual subject
Visual metaphor

NO actual image prompts.

Outputs:

latest_storyboard.json

Visual Director Agent

Consumes storyboard.

Converts abstract scenes into visual direction.

Example:

Foreground

Midground

Background

Lighting

Camera style

Composition

Texture

Visual world

Outputs:

latest_visual_plan.json

Image Prompt Agent

Consumes visual plan.

Produces one final image-generation prompt per scene.

Outputs:

latest_final_prompts.txt

IMPORTANT ARCHITECTURE DECISIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

We intentionally split:

Storyboard

↓

Visual Director

↓

Image Prompt Engineer

instead of combining them.

Reason:

Storyboard should understand storytelling.

Visual Director should understand cinematography.

Prompt Engineer should understand image models.

Each agent has ONE responsibility.

IMAGE QUALITY LESSONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

We discovered several important things.

Bad approach:

Prompt Engineer generating specific visual scenes.

Example:

Miami street

Vice City

Police chase

Palm trees

This is hardcoding.

Good approach:

Storyboard outputs structure.

Visual Director derives visual language FROM story.

Image Prompt Agent converts that structure into prompts.

Everything should be generated from the story.

Before suggesting any architecture:

Understand the existing pipeline.

Preserve modularity.

Avoid hardcoding.

Think about scalability.

Assume Vice Studio will eventually produce 30–100 Shorts per day across many niches.

When proposing changes, always explain:

1. Why the current architecture is insufficient.

2. Why the new architecture is more generic.

3. How it preserves future scalability.

Do not recommend shortcuts that reduce modularity.
